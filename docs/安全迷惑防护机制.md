## 1. 背景与目标



### 1.2 目标
在“限制型防御”（防火墙/限流）之上，增加**欺骗性防御（Honeypot & Deception）**：

1. **迷惑**：布置假密钥、假密码、假备份、假管理员数据，让攻击者找不到/误认真实文件；
2. **触发即反应**：攻击者触碰任何陷阱，立即触发自动封禁 + 完整取证 + 告警；
3. **真实文件保底**：对真实敏感文件做完整性监控，被篡改第一时间告警留证。

### 1.3 安全边界声明（“反攻”的合法等价物）
**本方案不包含任何主动入侵/攻击攻击者系统的能力**（主动“打回去”在国内外均属违法，且误伤风险极高）。
合法且等效的“反攻”= 蜜罐路径 **秒封 IP（72h）** + **取证快照** + **告警**，让攻击者被困在假数据中、浪费时间并留下证据。

## 3. 部署内容（由外到内）

### 3.1 ufw 防火墙收紧
- 默认策略：**拒绝入站**，仅放行 **22 / 80 / 443**，另按用户要求放行 **3001**（uptime-kuma 监控平台，2026-09-22 重新开放）。

### 3.2 Docker 端口收口（消除公网直连后门）
| 服务 | 修改前 | 修改后 |
|---|---|---|
| 后端 API (8000) | `0.0.0.0:8000` 公网可直连 ⚠️ | `127.0.0.1:8000` 仅本机（nginx 代理 /api → 正常） |
| uptime-kuma (3001) | 公网 → 临时127.0.0.1 → **按用户要求恢复公网** | `0.0.0.0:3001` |

- 修改文件：`docker-compose.yml`、`docker-compose.secure.yml`（同步），git 提交 `d0d88a9`。
- 备份：`docker-compose.yml.bak-20260922-143803`。

### 3.3 fail2ban（4 个 jail）
| Jail | 监控日志 | 触发阈值 | 惩罚 |
|---|---|---|---|
| sshd | sshd 认证 | 5 次失败 / 10min | 封 24h |
| nginx-login | /var/log/nginx/access.log（401） | 20 次 / 15min | 封 6h |
| **nginx-honeypot** | /var/log/nginx/honeypot.log | **1 次命中即封** | 封 72h |
| recidive | /var/log/fail2ban.log | 3 次重复违规 | 封 7 天 |

忽略名单：本机回环、内网段、服务器自身公网 IP（<服务器公网 IP>）。

### 3.4 Web 蜜罐路径矩阵（nginx）
攻击者扫描以下路径 → 返回**假密钥内容**（200）→ 写入 honeypot.log → fail2ban 秒封：

`/.git/  /.env  /.env.bak  config.php  .DS_Store  web.config  www.zip  backup*.zip|tar|gz|sql  /data/  /phpmyadmin  /wp-admin  /wp-login.php  /administrator  /server-status`

- 配置：`/etc/nginx/snippets/honeypot.conf`（location 块）+ `/etc/nginx/conf.d/honeypot-log.conf`（log_format）
- 站点配置改动前备份：`/opt/security/nginx-backups/`
- 真实业务路径（/api、/、/admin 前端路由）不受影响。

### 3.5 文件层诱饵（Honeytokens）
| 诱饵文件 | 伪装内容 | 用途 |
|---|---|---|
| `/opt/fake-secrets/.env` | 假 JWT / LLM / 数据库密钥、假管理员邮箱 | 让攻击者以为拿到了真实密钥 |
| `/home/ubuntu/备份/passwords.txt` | 假 root/ubuntu/admin/luchen 密码表 | 消耗攻击者破解时间 |
| `/opt/fake-backend/data/users/admin.json` | 假超级管理员账号与假哈希 | 让攻击者以为找到了真实管理员数据 |

真实文件位置（未移动）：项目 `apps/backend/.env`（仅 ubuntu 可读）、Docker 数据卷 `hr-ai-resume-selection_backend-data`（仅容器内 appuser 可写）。

### 3.6 tripwire 真实文件完整性监控
- 监控对象（16 项哈希）：真实 `.env`、`app.py`、`auth.py`、`config.py`、`docker-compose.yml`、`sshd_config`、nginx 站点/蜜罐配置、`authorized_keys`、**容器内 `/app/data/users/*.json`（管理员数据）**。
- 频率：cron 每 5 分钟（`/etc/cron.d/tripwire`）。
- 触发：→ 证据快照 `/opt/security/evidence/<时间戳>/` + 告警 `/opt/security/alerts/alerts.log` + 系统日志(tripwire)。

## 4. 触发 → 反应链路

```
攻击者访问蜜罐路径(/.env 等)
  → nginx 返回假密钥内容(200) + 写入 /var/log/nginx/honeypot.log
  → fail2ban [nginx-honeypot] 即刻封禁来源 IP(72h)
  → （shell 级入侵时）honeytokens 假文件被读取 → 徒劳
  → （真实文件被改时）tripwire 5 分钟内告警 + 取证快照 + 系统日志
```

# 已关闭端口走隧道（示例：openclaw 18789）
